1. Executive Summary

Il progetto e una beta molto avanzata ma ancora fragile. Ha tante funzioni reali: gestionale servizi, agenzie, import email/PDF, bus, driver app, pricing, analytics, notifiche, cron, QR, WhatsApp e flotta.

Tecnicamente compila: pnpm typecheck passa, pnpm build passa, mentre pnpm lint fallisce con 35 errori e 42 warning.

Il problema principale non e la mancanza di funzionalita, ma la concentrazione di molta logica operativa in file enormi, con schema Supabase in evoluzione, API numerose, migrazioni duplicate e controlli auth non sempre uniformi.

Stato generale: beta operativa / staging avanzato. Per uso quotidiano reale resta rischioso senza hardening mirato.

2. Cosa Funziona

  • Build production: pnpm build completato correttamente con Next 16.2.2. Coinvolge app/, app/api/, next.config.ts.
  • Auth base e ruoli: esiste un layout protetto con sessione, ruoli e tenant. File: app/(app)/layout.tsx, lib/server/pricing-auth.ts.
  • API protette con helper condiviso: molte route usano authorizePricingRequest e authorizeServiceRoleRequest.
  • Driver app: pagina driver, dati assegnati, cambio password e prompt PWA sono presenti. File: app/(app)/driver/page.tsx, app/api/ops/driver-data/route.ts, components/driver/PwaInit.tsx.
  • Piano giorno / assegnazioni: flusso ricco con servizi, autisti, viaggi, assegnazioni, auto-assign ed export. File: app/(app)/piano-giorno/page.tsx, app/api/ops/piano-giorno/*.
  • Import email/PDF: presenti parser, preview, conferma, salvataggio bozze e deduplica. File: app/(app)/inbox/page.tsx, app/api/email/*, lib/server/agency-pdf-import.ts.
  • Pricing: struttura ampia con listini, margini, regole, storico e simulator. File: app/(app)/pricing/page.tsx, app/api/pricing/*, lib/server/pricing-matching.ts.

3. Cosa Non Funziona

  • Lint non passa. alta La Definition of Done non e rispettata. Errori in varie pagine agency, dispatch, Medmar AR e PWA driver.
  • Migrazioni Supabase con numeri duplicati. alta Duplicati in 0009, 0025, 0067, 0074, 0100, 0140. Rischio ambienti non allineati.
  • Tipi Supabase incompleti o obsoleti. alta lib/supabase/types.ts non rappresenta tutto lo schema usato dal codice.
  • API fragili rispetto allo schema. alta Alcune route usano colonne recenti come phone_e164, time_from, time_to, pickup_hotel, porto_bruno, approval_status.

4. Cosa E Incompleto O Fragile

  • File troppo grandi: bus-network/page.tsx 181 KB, pricing/page.tsx 148 KB, piano-giorno/page.tsx 111 KB, app/api/ops/bus-network/route.ts 100 KB.
  • Auth non centralizzata nel proxy: proxy.ts e quasi pass-through. Ogni API deve proteggersi correttamente da sola.
  • Health/config parzialmente pubblici: app/health/page.tsx e app/api/health/route.ts espongono presenza/assenza delle env.
  • Webhook WhatsApp: verificato token GET, ma la firma Meta sul POST e da rafforzare.

7. Sicurezza / Auth / Config

Aspetti positivi: nessun segreto tracciato trovato via git ls-files; .env e .env.local sono ignorati; molte API usano role check e tenant filter; QR pubblico rimanda a scan autenticato.

Rischi: service role usato molto, cron dipendenti da CRON_SECRET, webhook WhatsApp da firmare, auth custom in alcune API, fallback dev secret in lib/server/agency-action-token.ts.

8. Prontezza Per Produzione

Valutazione secca: PRONTO SOLO CON CORREZIONI.

La build passa e il prodotto ha molti flussi reali, ma non e ancora abbastanza solido per uso operativo senza interventi. I rischi maggiori sono lint KO, schema/migrazioni non blindati, file monolitici, route service-role numerose e flussi critici non coperti da test end-to-end.
